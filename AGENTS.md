# Building Rules maintenance

This repository owns the reusable engineering Skill and its small native host
adapters under `plugins/building-rules/`. Preserve complete user outcomes while
reducing unnecessary investigation, implementation, checking and records.

Keep the lifecycle core short. Put conditional examples in references and load
only the relevant case. A case states its trigger, failure, minimum response,
stopping condition, exception and evidence. Separate owner policy, established
contracts, recommendations and historical reports. Never turn an anecdote into
a universal rule or classify source-file lines as business value automatically.

Use native plugin packaging and the Python standard library. Do not add a task
runner, database, mandatory model reviewer, fixed development ceremony or new
approval layer. Other Skills remain optional; do not create competing state owners.
Never publish private global instructions, local task records or credentials.

Preserve unrelated changes. Test changed hook behavior with
`python3 -m unittest discover -s tests -v`; run the available Skill and plugin
validators, and native manifest validation when available. Structural checks prove
package consistency; hook execution proves emitted context; neither proves model
compliance or improved productivity. Retain failures and report untested hosts.

Keep plugin versions aligned. For an authorized publication, commit source first,
push without rewriting history, and verify the remote ref and CI. Repository push,
aggregate marketplace registration, local installation and behavior evaluation are
separate results. Stage only intended files; use no AI co-author trailer.
